## 1. Структура доклада и слайды презентации

### Слайд 1: Титульный
- **Проект:** Suburban Transit Planner — интеллектуальный пригородный навигатор по Санкт-Петербургу и Ленинградской области.
- **Цель работы:** Проектирование и разработка высокопроизводительного сервиса поиска прямых и стыковочных пригородных маршрутов с гарантированной отказоустойчивостью при сбоях внешних поставщиков расписания.

### Слайд 2: Проблематика и требования
- В пригородном сообщении СПб (Финляндское, Приозерское, Балтийское направления) пассажиры регулярно сталкиваются с задержками поездов, отменами рейсов и сложными пересадками (например, на станции Зеленогорск).
- Внешние API расписаний (Яндекс.Расписания) имеют суточные квоты (500 запросов/сутки на тарифе разработчика) и подвержены сетевым сбоям.
- **Задача системы:** Обеспечить безотказную работу ($99.9\%$ uptime), отсекать рискованные пересадки и мгновенно переключаться на локальный расчетный граф при авариях.

### Слайд 3: Архитектура системы
- **Frontend:** React 18 + TypeScript + Vite + Tailwind CSS (SPA с карточками маршрутов, индикатором статуса сети и бейджами риска стыковок).
- **Backend:** FastAPI (Python 3.12, ASGI) с асинхронным вводом-выводом.
- **Cache-слой:** Redis 7 (In-Memory кэширование Cache-Aside с TTL=300с).
- **Database:** PostgreSQL 16 (реестр узловых станций и журнал телеметрии).
- **Оркестрация:** Docker Compose с мультистейдж-сборкой и healthcheck-пробами.

### Слайд 5: Архитектурные паттерны отказоустойчивости
1. **Circuit Breaker (Автомат защиты):**
   - Состояния: `CLOSED` $\rightarrow$ `OPEN` $\rightarrow$ `HALF_OPEN`.
   - Порог срабатывания: 5 последовательных сетевых сбоев или HTTP 429.
   - Таймаут остывания: 60 секунд.
2. **Graceful Degradation (Мягкая деградация):**
   - При сбое внешнего API сервис **не падает с 500 ошибкой**, а возвращает `200 OK` с флагом `"is_degraded": true` и `"system_status": "DEGRADED_OFFLINE"`.
   - Ответ строится по локальному графу расписания ОЖД.

### Слайд 6: Алгоритм расчета стыковок и пешеходный буфер
- Алгоритм обхода узловых станций (Junction Hubs).
- Допустимое окно стыковки: от 5 до 45 минут.
- **Бизнес-правило безопасности пересадки:**
  - Пешеходный буфер между платформами: **7 минут**.
  - Если время ожидания между поездами $< 7$ минут, система маркирует пересадку флагом `is_tight_connection: true` и подсвечивает карточку предупреждающим бейджем в UI.
- Фильтрация отмененных поездов (`status == "CANCELLED"`).
