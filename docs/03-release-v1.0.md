## 1. Назначение и цели этапа «Release»

Этап **Release** представляет собой переход от прототипа минимально жизнеспособного продукта (**MVP**, сданного 29.10.2026) к полнофункциональной релизной версии системы перед передачей на фазы масштабного тестирования (Unit, Integration & Load Testing).

### Основные цели этапа:
1. **Интеграция с реальным внешним сервисом данных:** переход от автономного тестового генератора к боевому шлюзу **API Яндекс.Расписаний v3.0** с использованием активного ключа разработчика.
2. **Переход на официальные коды станций ОЖД:** внедрение реальных классификаторов станций Октябрьской железной дороги (Финляндский вокзал, Зеленогорск, Выборг, Девяткино, Приозерск и др.) с сохранением обратной совместимости с тестовыми кодами.
3. **Реализация парсера расписания (`yandex_client.py`):** разбор сегментов и ниток поездов, классификация типов подвижного состава («Ласточка / Экспресс» vs «Стандартная пригородная электричка»), учет перевозчиков (АО «СЗППК»).
4. **Завершение всех User Stories:** полная реализация бизнес-логики пользовательских историй 1–4.
5. **Логирование и трассировка:** структурированные JSON-логи по стандартам 12-Factor App для мониторинга попаданий в кэш (Cache Hit/Miss), сработки Circuit Breaker и расчетов графа.
6. **Маркировка релиза в системе контроля версий:** выпуск тега `v1.0.0`.

## 3. Детали интеграции с API Яндекс.Расписаний

- **Подключенный сервис:** API Яндекс.Расписаний (Кабинет разработчика).
- **Используемый API-ключ:** `9767995c-25ed-4c04-a367-0a8368dee2e2`.
- **Действующий тариф:** Бесплатный тариф разработчика (до 500 запросов в сутки).
- **Базовый URL:** `https://api.rasp.yandex.net/v3.0`.
- **Реализованные методы шлюза:**
  1. `/search/` — поиск расписания между станциями с параметрами `transport_types=suburban`, `date=YYYY-MM-DD`.
  2. `/nearest_stations/` — обнаружение географических координат и кодов станций.
  3. `/thread/` — получение нитки движения поезда со всеми промежуточными остановками.

## 4. Архитектурные доработки и логирование

В рамках релиза v1.0.0 добавлены ключевые архитектурные улучшения:
1. **Нормализатор кодов (`normalize_station_code`):**
   Позволяет принимать запросы как по реальным кодам ЕСР/Яндекса (`s9602497`), так и по устаревшим/тестовым алиасам (`s9600370`), предотвращая ошибки клиентов.
2. **Парсер сегментов (`parse_yandex_response`):**
   - Автоматически вычисляет длительность в минутах.
   - Корректно обрабатывает поезда, идущие через полночь (переход суток).
   - Извлекает номера поездов и информацию о перевозчике (АО «СЗППК»).
3. **Структурированное логирование трассировки:**
   - `[CACHE HIT] Key '...' found in Redis. Returned N routes instantly.`
   - `[CACHE MISS] Key '...' not in Redis. Initiating provider query / graph engine...`
   - `[LIVE YANDEX RASP] Successfully retrieved N live suburban trains.`
   - `[CIRCUIT BREAKER: OPEN] External Yandex API is tripped. Skipping network call.`
   - `[TRANSFER MATCH] Hub: Зеленогорск, Leg1: 6115, Leg2: 6141, Wait: 20m, Buffer: 7m, Tight: False`
